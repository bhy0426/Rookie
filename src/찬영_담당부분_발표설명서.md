# 찬영 담당 부분 발표 설명서

이 문서는 `Usage` 페이지와 문법 상세 페이지를 발표할 때 이해하고 설명하기 위한 자료입니다.  
전문용어는 바로 옆에 괄호로 풀어 적었습니다.

## 1. 전체 역할 요약

내가 맡은 부분은 숨 언어의 문법을 사용자가 쉽게 탐색할 수 있게 만드는 사용 페이지입니다.

핵심은 28개의 문법을 각각 파일로 따로 만들지 않고, 하나의 데이터 파일과 하나의 상세 페이지 컴포넌트(화면을 구성하는 React 함수)로 처리한 것입니다.

발표 문장:

> 제 역할은 숨 언어 문법을 검색하고, 미리보고, 상세 페이지에서 확인할 수 있는 사용 페이지를 구현하는 것이었습니다. 28개의 문법 페이지를 각각 따로 만들지 않고, 문법 데이터 배열(여러 데이터를 순서대로 담는 목록)과 URL 번호를 이용해 하나의 상세 페이지에서 동적으로 보여주도록 만들었습니다.

## 2. 담당 파일 목록

내 담당 기능과 직접 관련 있는 파일은 다음과 같습니다.

- `pages/Usage.tsx`
- `subpages/grammar/GrammarDetail.tsx`
- `components/EditorBlock.tsx`
- `data/grammarData.ts`
- `App.tsx`
- `App.css`
- `pic/grammar/1.png`부터 `pic/grammar/28.png`

## 3. `pages/Usage.tsx`

`Usage.tsx`는 사용 페이지의 메인 화면입니다.

이 파일에서 하는 일:

- 문법 검색창을 보여줍니다.
- 카테고리(문법을 주제별로 나눈 분류) 버튼을 보여줍니다.
- 검색어와 카테고리에 맞는 문법 카드 목록을 보여줍니다.
- 문법 카드를 누르면 미리보기 영역에 해당 문법 설명과 자료 이미지를 보여줍니다.
- `상세 보기`를 누르면 `/grammar/번호` 상세 페이지로 이동합니다.

### 주요 컴포넌트

`Usage` 컴포넌트(화면을 구성하는 React 함수):

- 사용 페이지 전체를 담당하는 부모 컴포넌트입니다.
- 부모 컴포넌트(다른 컴포넌트를 감싸고 데이터를 관리하는 컴포넌트)이기 때문에 검색어, 선택된 카테고리, 미리보기 문법을 상태로 관리합니다.

`GrammarCard` 컴포넌트:

- 문법 카드 하나를 보여주는 자식 컴포넌트입니다.
- 자식 컴포넌트(부모에게 데이터를 받아 화면 일부를 담당하는 컴포넌트)는 직접 전체 상태를 바꾸지 않고, 부모가 넘겨준 함수를 호출합니다.

### 사용한 Hook

`useState`(상태 저장 Hook: 값이 바뀌면 화면을 다시 그리게 하는 기능)

사용 위치:

- `searchText`: 검색어 저장
- `selectedCategory`: 선택된 카테고리 저장
- `previewItem`: 미리보기로 보여줄 문법 저장

발표 설명:

> useState는 사용자가 입력하거나 선택한 값을 저장하기 위해 사용했습니다. 검색어가 바뀌거나 카테고리를 누르면 상태가 바뀌고, React가 화면을 다시 렌더링합니다.

`useEffect`(렌더링 후 실행 Hook: 화면이 그려진 뒤 실행되는 기능)

사용 위치:

- 페이지에 처음 들어왔을 때 검색창에 자동으로 포커스(입력할 수 있게 커서를 올려두는 동작)를 줍니다.

발표 설명:

> useEffect는 화면이 처음 그려진 뒤 실행되어야 하는 작업에 사용했습니다. 여기서는 사용 페이지에 들어오면 검색창에 바로 입력할 수 있도록 자동 포커스를 적용했습니다.

`useRef`(참조 Hook: 화면 요소를 직접 가리키거나 리렌더링되어도 값을 유지하는 기능)

사용 위치:

- `searchInputRef`: 검색창 input 요소를 가리킵니다.
- `previewSectionRef`: 미리보기 영역을 가리킵니다.

발표 설명:

> useRef는 실제 화면 요소를 가리키기 위해 사용했습니다. 검색창에 자동 포커스를 주거나, 미리보기 버튼을 눌렀을 때 미리보기 영역으로 이동할 때 사용했습니다.

`useMemo`(계산 결과 재사용 Hook: 필요한 값이 바뀔 때만 다시 계산하는 기능)

사용 위치:

- `filteredGrammar`: 검색어와 카테고리에 맞는 문법 목록 계산

발표 설명:

> useMemo는 검색 결과를 계산할 때 사용했습니다. 검색어 또는 카테고리가 바뀔 때만 문법 목록을 다시 필터링하고, 그 외에는 이전 계산 결과를 재사용합니다.

`useCallback`(함수 재사용 Hook: 함수를 매번 새로 만들지 않고 재사용하는 기능)

사용 위치:

- `handleCategoryChange`: 카테고리 버튼 클릭 함수
- `handlePreview`: 미리보기 버튼 클릭 함수

발표 설명:

> useCallback은 자식 컴포넌트에 전달하는 함수를 재사용하기 위해 사용했습니다. 문법 카드에 미리보기 함수를 props로 전달하기 때문에, 불필요하게 함수가 계속 새로 만들어지는 것을 줄였습니다.

### props 설명

`props`(부모 컴포넌트가 자식 컴포넌트에게 전달하는 데이터)

`Usage`는 `GrammarCard`에게 다음 값을 전달합니다.

- `item`: 문법 하나의 데이터
- `isSelected`: 현재 미리보기 중인 문법인지 알려주는 값
- `onPreview`: 미리보기 버튼을 눌렀을 때 실행할 함수

발표 설명:

> 부모 컴포넌트인 Usage가 문법 데이터와 미리보기 함수를 GrammarCard에 props로 전달했습니다. 자식 컴포넌트는 데이터를 직접 바꾸지 않고, 전달받은 함수를 호출해서 부모의 상태를 바꾸도록 했습니다.

## 4. `subpages/grammar/GrammarDetail.tsx`

`GrammarDetail.tsx`는 문법 상세 페이지입니다.

이 파일에서 하는 일:

- `/grammar/1`, `/grammar/21`처럼 주소에 들어있는 번호를 읽습니다.
- 번호에 맞는 문법 데이터를 `grammarData`에서 찾습니다.
- 제목, 설명, 단축키, 사용 예시, 주의사항, 자료 화면을 보여줍니다.
- 단축키 복사 버튼을 제공합니다.
- 이전 문법과 다음 문법으로 이동하는 링크를 보여줍니다.
- `EditorBlock` 컴포넌트에 문법별 체험 데이터를 전달합니다.

### 사용한 Hook

`useParams`(URL 파라미터 Hook: 주소에 들어있는 값을 가져오는 기능)

예:

- `/grammar/21`이면 `id` 값이 `"21"`이 됩니다.

발표 설명:

> useParams를 사용해서 주소에 있는 문법 번호를 읽었습니다. 그래서 상세 페이지 파일을 28개 만들지 않고, 하나의 GrammarDetail 컴포넌트가 번호에 맞는 문법 데이터를 찾아 보여줄 수 있습니다.

`useState`(상태 저장 Hook)

사용 위치:

- `copied`: 단축키 복사 버튼을 눌렀는지 저장

발표 설명:

> useState는 복사 버튼의 상태를 관리하기 위해 사용했습니다. 버튼을 누르면 잠시 동안 문구가 '복사됨'으로 바뀝니다.

`useMemo`(계산 결과 재사용 Hook)

사용 위치:

- `neighbors`: 이전 문법과 다음 문법 계산

전문용어:

- 인덱스(배열의 자리): 배열 안에서 몇 번째 위치인지 나타내는 숫자입니다. 첫 번째는 0입니다.

발표 설명:

> useMemo를 사용해서 현재 문법의 인덱스를 기준으로 이전 문법과 다음 문법을 계산했습니다. 현재 번호가 바뀔 때만 다시 계산되도록 했습니다.

`useEffect`(렌더링 후 실행 Hook)

사용 위치:

- 복사 버튼을 누른 뒤 2초 후 `복사됨` 문구를 다시 `복사`로 바꿉니다.

발표 설명:

> useEffect는 복사 완료 상태를 일정 시간 뒤 자동으로 초기화하기 위해 사용했습니다.

### 핵심 구조

```tsx
const currentId = Number(id);
const currentIndex = grammarData.findIndex((item) => item.id === currentId);
const currentData = grammarData[currentIndex];
```

설명:

- `Number(id)`: URL에서 받은 문자열 번호를 숫자로 바꿉니다.
- `findIndex`: 배열에서 조건에 맞는 항목의 위치를 찾습니다.
- `currentData`: 실제 화면에 보여줄 문법 데이터입니다.

발표 문장:

> URL의 번호를 숫자로 바꾼 뒤, grammarData 배열에서 같은 id를 가진 문법을 찾습니다. 찾은 데이터를 상세 페이지에 출력하기 때문에 하나의 파일로 여러 문법 페이지를 처리할 수 있습니다.

## 5. `components/EditorBlock.tsx`

`EditorBlock.tsx`는 체험형 에디터 화면입니다.

이 파일에서 하는 일:

- 문법 데이터 안의 `content`를 받아 화면에 보여줍니다.
- `공개 기능`, `관리 값`, `내부 처리` 탭을 보여줍니다.
- 탭을 누르면 해당 영역의 변수, 함수, 규칙 목록을 보여줍니다.

### 탭 의미

`공개 기능`:

- 사용자가 밖에서 직접 사용할 수 있는 기능입니다.
- 예: `이동()`, `체력읽기()`

`관리 값`:

- 객체가 상태를 기억하고 관리하는 값입니다.
- 예: `체력`, `공격력`

`내부 처리`:

- 밖에서 직접 건드리지 않아도 되는 내부 동작입니다.
- 예: `상태계산()`, `충돌검사()`

발표 설명:

> 체험형 에디터는 객체 안의 요소를 역할별로 나누어 보여주는 화면입니다. 어려운 public, protected, private 같은 용어 대신 공개 기능, 관리 값, 내부 처리라는 표현을 사용했습니다.

### 사용한 Hook

`useState`(상태 저장 Hook)

사용 위치:

- `activeTab`: 현재 선택된 탭 저장

발표 설명:

> useState를 사용해서 현재 어떤 탭이 선택되었는지 저장했습니다. 탭을 누르면 상태가 바뀌고, 선택한 영역의 내용만 화면에 표시됩니다.

`useMemo`(계산 결과 재사용 Hook)

사용 위치:

- 각 탭에 들어있는 항목 개수 계산

발표 설명:

> useMemo를 사용해서 공개 기능, 관리 값, 내부 처리에 각각 몇 개의 항목이 있는지 계산했습니다. 데이터가 바뀔 때만 다시 계산됩니다.

### props 설명

`EditorBlock`은 `data`라는 props를 받습니다.

`data` 안에는 다음 값이 들어 있습니다.

- `name`: 에디터에 표시할 객체 이름
- `summary`: 짧은 설명
- `public`: 공개 기능 목록
- `protected`: 관리 값 목록
- `private`: 내부 처리 목록
- `warnings`: 주의사항 목록

발표 문장:

> GrammarDetail이 현재 문법의 content 데이터를 EditorBlock에 props로 전달합니다. EditorBlock은 이 데이터를 받아 탭 형태의 체험형 화면으로 보여줍니다.

## 6. `data/grammarData.ts`

`grammarData.ts`는 28개 문법 데이터를 모아둔 파일입니다.

이 파일에서 하는 일:

- 문법 번호를 저장합니다.
- 문법 제목을 저장합니다.
- 카테고리를 저장합니다.
- 단축키를 저장합니다.
- 설명, 예시, 주의사항을 저장합니다.
- 문법별 자료 이미지 경로를 연결합니다.
- `EditorBlock`에 넘길 체험형 데이터도 저장합니다.

### 주요 타입

`GrammarItem`(문법 하나의 전체 데이터 모양)

포함하는 값:

- `id`: 문법 번호
- `title`: 문법 제목
- `category`: 카테고리
- `shortcut`: 단축키
- `description`: 설명
- `example`: 사용 예시
- `caution`: 주의사항
- `image`: 자료 이미지
- `content`: 에디터에 보여줄 세부 데이터

`GrammarMember`(에디터 안의 항목 하나)

포함하는 값:

- `name`: 항목 이름
- `value`: 항목 값
- `kind`: 종류

`kind` 값:

- `variable`: 변수(값을 저장하는 이름)
- `function`: 함수(명령을 묶어 이름을 붙인 것)
- `property`: 속성(객체가 가진 값이나 특징)
- `rule`: 규칙(문법에서 지켜야 하는 형식)

### 이미지 연결 방식

```tsx
export const grammarData: GrammarItem[] = grammarItems.map((item) => ({
  ...item,
  image: new URL(`../pic/grammar/${item.id}.png`, import.meta.url).href
}));
```

설명:

- `map`: 배열의 각 항목을 다른 형태로 바꾸는 함수입니다.
- `...item`: 스프레드 문법(기존 객체의 값을 그대로 복사하는 문법)입니다.
- `new URL`: 이미지 파일 위치를 안전하게 연결합니다.
- `import.meta.url`: 현재 파일의 위치를 기준으로 경로를 계산하게 합니다.

발표 문장:

> 문법 이미지도 id 번호와 맞춰 자동으로 연결했습니다. 1번 문법은 1.png, 21번 문법은 21.png처럼 연결됩니다.

## 7. `App.tsx`

`App.tsx`는 전체 페이지 라우팅(주소에 따라 어떤 화면을 보여줄지 정하는 기능)을 담당합니다.

내 담당 부분과 관련된 라우트:

```tsx
<Route path="/usage" element={<Usage />} />
<Route path="/grammar/:id" element={<GrammarDetail />} />
```

설명:

- `/usage`: 사용 페이지를 보여줍니다.
- `/grammar/:id`: 문법 상세 페이지를 보여줍니다.
- `:id`: 동적 파라미터(주소에서 바뀌는 값)입니다.

발표 문장:

> /grammar/:id 라우트를 사용해서 28개의 상세 페이지를 하나의 GrammarDetail 컴포넌트로 처리했습니다. 주소의 id 값만 바뀌면 같은 컴포넌트가 다른 문법 데이터를 보여줍니다.

### ScrollToTop

`ScrollToTop`은 페이지를 이동할 때 스크롤을 맨 위로 올리는 컴포넌트입니다.

사용한 Hook:

- `useLocation`: 현재 주소 정보를 가져오는 Hook입니다.
- `useEffect`: 주소가 바뀐 뒤 스크롤을 맨 위로 올립니다.

발표 문장:

> 상세보기를 눌렀을 때 이전 페이지의 스크롤 위치가 남는 문제가 있어서, 주소가 바뀔 때마다 화면을 맨 위로 올리는 ScrollToTop 컴포넌트를 추가했습니다.

## 8. `App.css`

`App.css`는 화면 디자인을 담당합니다.

내 담당 부분과 관련된 스타일:

- `usagePage`: 사용 페이지 전체
- `toolbarSection`: 검색창과 카테고리 영역
- `grammarGrid`: 문법 카드 목록
- `grammarCard`: 문법 카드 하나
- `previewSection`: 미리보기 영역
- `previewImage`: 자료 화면 이미지
- `detailPage`: 문법 상세 페이지
- `grammarImageSection`: 상세 페이지의 자료 이미지 영역
- `editorBlock`: 체험형 에디터 전체

전문용어:

- CSS 클래스(디자인을 적용하기 위해 HTML 요소에 붙이는 이름)
- grid(격자 배치: 여러 요소를 행과 열로 정렬하는 CSS 방식)
- responsive(반응형: 화면 크기에 따라 배치가 바뀌는 디자인)

발표 문장:

> App.css에서는 사용 페이지, 문법 카드, 미리보기, 상세 페이지, 체험형 에디터의 화면 배치를 정리했습니다. 화면 크기가 줄어들어도 카드와 에디터가 세로로 정렬되도록 반응형 스타일도 적용했습니다.

## 9. `pic/grammar/1.png` ~ `pic/grammar/28.png`

이 폴더에는 문법별 자료 이미지가 들어 있습니다.

연결 방식:

- 1번 문법은 `1.png`
- 2번 문법은 `2.png`
- 21번 문법은 `21.png`
- 28번 문법은 `28.png`

원본 스크린샷에서 제목, 본문 설명, 표는 제거하고 자료 화면 부분만 남겼습니다.

발표 문장:

> 문법 자료 이미지는 번호 순서대로 저장했습니다. grammarData의 id와 이미지 파일 이름을 맞춰서, 문법을 선택하면 해당 번호의 자료 화면이 자동으로 표시됩니다.

## 10. 발표용 전체 흐름

발표할 때는 이 순서로 말하면 됩니다.

1. `/usage` 페이지에서 문법 목록을 보여줍니다.
2. 사용자가 검색어를 입력하거나 카테고리를 선택합니다.
3. `useMemo`로 조건에 맞는 문법만 필터링합니다.
4. 문법 카드의 `미리보기`를 누르면 `useState`로 선택 문법이 바뀝니다.
5. `useRef`로 미리보기 영역까지 화면을 이동합니다.
6. `상세 보기`를 누르면 `/grammar/번호` 주소로 이동합니다.
7. `useParams`가 URL 번호를 읽습니다.
8. `grammarData`에서 해당 번호의 문법을 찾습니다.
9. 상세 페이지가 설명, 단축키, 예시, 자료 이미지, 체험 에디터를 보여줍니다.
10. 이전/다음 문법 링크로 다른 문법으로 이동할 수 있습니다.

## 11. 짧은 발표 대본

> 제 담당 부분은 숨 언어 문법을 검색하고 상세히 확인할 수 있는 사용 페이지입니다.  
> 처음에는 문법마다 페이지를 따로 만들 수 있지만, 그렇게 하면 28개의 파일이 필요하고 관리가 어려워집니다.  
> 그래서 저는 문법 정보를 `grammarData` 배열에 저장하고, `/grammar/:id` 라우트를 사용해서 하나의 상세 페이지가 URL 번호에 따라 다른 문법을 보여주도록 구현했습니다.  
> 사용 페이지에서는 `useState`로 검색어와 선택된 문법을 관리하고, `useMemo`로 검색 결과를 계산하며, `useCallback`으로 자식 카드에 전달하는 함수를 재사용했습니다.  
> 또한 `useRef`를 사용해 미리보기 버튼을 눌렀을 때 미리보기 영역으로 이동하게 했고, `useParams`를 사용해 상세 페이지에서 URL 번호에 맞는 문법 데이터를 불러왔습니다.  
> 결과적으로 사용자는 문법을 검색하고, 미리보고, 상세 예시와 자료 화면까지 확인할 수 있습니다.
